## What it is

eTop University is eTop's public help and learning site: self-help guides for clients, eTop process
pages, policies and the team page. It runs **Astro + Starlight** for the look and navigation, with
**EmDash** (Cloudflare's open-source CMS, built on Astro) as the content store. eTop staff edit pages
in a browser at `/_emdash/admin` and publish without touching git.

It is **not** a client portal, it holds no client data, and nothing on it needs a login to read.
Only the editor (`/_emdash`) is behind a login.

## How it is built

| Path | What it is | Owner lane |
|---|---|---|
| `astro.config.mjs` | Astro 7 + Starlight 0.42 + `emdash` 1.1 on `@astrojs/cloudflare` (server output). Access sign-in via EmDash's `access()` adapter; new users `defaultRole: 40` (Editor). | core |
| `src/pages/[...slug].astro` | Loads the EmDash `docs` entry whose slug is the URL path and renders it in `StarlightPage`. The sidebar comes from the EmDash menu `docs-sidebar`, the TOC from the page's headings. Existing pages get the trailing-slash 308; missing pages return a real 404. Sitemaps are built from EmDash. | core |
| `src/lib/pt.ts`, `src/components/pt/` | Portable Text back to Starlight markup: nested lists and list continuations, asides, tables, `<details>`, images (with their GitBook width/height), code. | core |
| `src/_generated/step-hints.json` | Where each migrated screenshot, code block or extra paragraph sat inside a numbered step, by block key. The editor drops the in-step hints on save but keeps keys, so the theme puts saved pages back exactly (issues #13, #14). Generated from the seed by `scripts/emdash/step-hints.mjs` (`--check` for drift). Blocks added later have new keys and use the theme's own rules. | content / core |
| `src/plugins/university-boxes.mjs` | EmDash plugin (no server code): editor blocks *Note box: start/end* and *Collapsible section: start/end*. A box is stored flat (start marker, ordinary editable blocks, end marker) so editors can change the text inside it (issue #15). The theme rebuilds the box. | core |
| `src/stubs/satteri.mjs` | Stub for Starlight's native markdown engine, which cannot load in a Worker. Nothing compiles markdown at request time; any call throws loudly. | core |
| `/api/search` | Public search endpoint (EmDash full-text search, published pages only). The search box keeps Starlight's look. Pagefind can't index server-rendered pages, and `/_emdash/api/search` sits behind Access. | core |
| `src/worker.ts`, `wrangler.jsonc` | Worker entry (incl. the scheduled handler for timed publishing), bindings above | core / infra |
| `.emdash/seed.json` | Schema (collection `docs` and its fields), sidebar menu, all 119 pages (118 migrated + the editor how-to). Generated by `build-seed.mjs`, never hand-edited; `build-seed.mjs --check` fails on drift. | content |
| `scripts/emdash/` | Markdown to EmDash migration (`build-seed.mjs`), `d1-sql.mjs` (loads a **new** D1 from the seeded SQLite; idempotent; re-points menu links by slug, because `emdash seed` gives pages fresh IDs each run), `apply.mjs` (REST loader), `parity.mjs` (cutover gate). Own `package.json`. See `scripts/emdash/README.md`. | content / core |
| `wrangler.jsonc`, `scripts/infra/deploy.sh` | Worker config and bindings; build (env picked at build time), put the D1 schema in place, deploy, verify. From infra PR #6. | infra |
| `tests/e2e/` | Editor E2E (Playwright), the live-vs-preview visual diff, and `roundtrip.mjs` (real-editor save of every page on a LOCAL `astro dev`). Own `package.json`. See `tests/e2e/README.md`. | qa-docs |
| `public/.gitbook/assets/` | Images, still served as static files. Not moved into R2 in v1. | - |
| `src/content/docs/**/*.md` | The old markdown. After cutover it is the **migration source only**; edits made here no longer reach the site. | - |

**Content model** (collection `docs`): `title`, `description`, `body` (Portable Text), `sidebar_label`,
`template` (`doc` or `splash`), `frontmatter_extra`, `legacy_source`, `migration_hash`. The slug is the full
page path (`education/self-help-guides/backups`; home is `index`), so every URL kept its old address.

**Secrets** (names only; values are Worker secrets, never in git, `wrangler.jsonc` or `astro.config.mjs`):

## Deploy

```bash
bash scripts/infra/deploy.sh production                  # THE NORMAL WAY TO SHIP A CODE CHANGE (= --code-only); type 'production'
bash scripts/infra/deploy.sh preview                     # same, to the preview
bash scripts/infra/deploy.sh production --migrate        # only when an EmDash upgrade brings new core migrations; needs CLOUDFLARE_API_TOKEN (D1 Edit)
bash scripts/infra/deploy.sh production --load-content   # ONCE, at cutover (production D1 is empty); lead only, under a Change issue
bash scripts/infra/deploy.sh preview --load-content      # EMPTY or throwaway preview D1 only: schema + migrations + all pages + menu + search; resets seed pages
```

- **The env is picked at build time.** `@astrojs/cloudflare` writes a flattened `dist/server/wrangler.json` for
  `CLOUDFLARE_ENV`, and `wrangler deploy` follows it, so deploy takes no `--env`. The script sets `CLOUDFLARE_ENV` and checks the
  built Worker name. Commands that read `wrangler.jsonc` directly (`d1 execute`, `secret put`) need `--config wrangler.jsonc --env preview`.
- **Code-only is the default, and it refuses when it should not ship.** It compares the build's EmDash migration set
  (`.emdash/migrations.json`) with the `_emdash_migrations` rows in that D1, and the build's EmDash version with the
  `emdash=<version>` message on the currently deployed Worker version (every deploy writes one). Any difference prints
  `REFUSED` and points to `--migrate`. It touches no data, so editors' work is safe. Uses the wrangler login; no API token.
- **`wrangler deploy` never runs D1 migrations.** `--load-content` runs `scripts/emdash/out/d1-load.sql` (from `d1-sql.mjs`).
  It **overwrites pages with the seed**, so use it only on an empty D1: the preview before cutover, production once at cutover.
  Never again after editors start working. `--migrate` runs `emdash migrate`, which ignores the
  wrangler login and needs `CLOUDFLARE_API_TOKEN`. In CI, pass the reviewed fingerprint as `EMDASH_TARGET_FINGERPRINT`.
- Content-model changes (collections and fields) are a separate step. See EmDash's "Evolving a Deployed Site".
- Any binding added later (`CACHE`, `LOADER`) must be repeated under `env.preview`: bindings are not inherited. The adapter adds `IMAGES` and `ASSETS` itself.

**Confirm it worked:**

1. `GET <url>/` returns 200 with no login.
2. `GET <url>/_emdash/admin` with no login returns **302 to `etoptech.cloudflareaccess.com`**. A 200 here means Access is off: stop.
   `GET <url>/_emdash/api/content/docs` with no login is also a 302 to Access: Access covers the API too. A 401 from EmDash does not count.
   `deploy.sh` runs these checks and prints `VERIFY OK` or `VERIFY FAILED`.
3. Every sidebar page link resolves (`deploy.sh` checks it); after `--migrate`, `npx emdash migrate --check …` exits 0.
4. `npx wrangler tail [--env preview]` shows the cron line `"* * * * *" … Ok` once a minute.
5. Preview only, before cutover, all from `tests/e2e/` and `scripts/emdash/`:
   - `node parity.mjs --candidate <preview>`: every URL, title and main text matches the live site. Accepted differences
     are listed in `parity.mjs` (`ACCEPTED`): `/404` (Pages answered 200, a soft 404; the Worker answers 404) and `/e2e-test-page`
     (the E2E's unlisted test page; `noindex`, not in the sitemap). The gate also decodes Cloudflare email obfuscation, treats
     `/a` and `/a/` as one page, and counts absolute links to university.etop.tech as same-site.
   - `node visual-diff.mjs --candidate <preview>` (in `tests/e2e/`): home plus 5 docs, light and dark. Fails over 0.5% of all pixels,
     2% in any 200px band, or an 8px height change.
   - GitHub Actions **editor-e2e** (`gh workflow run editor-e2e -R etopple/university`, manual only): edit, publish and render
     end to end on the preview, then the visual diff. The secrets exist only in GitHub, so this is where it runs. GitHub only
     offers a manual workflow only once the file is on the repo's **default branch, `website`** (the old GitBook branch; Pages builds `starlight`).
     Until the workflow reaches `website`, it can't be run.

## Rebuild from zero

Node 22.22.2+ or 24.15+ (EmDash 1.1 requirement).

```bash
export CLOUDFLARE_ACCOUNT_ID=44c7bfb7295ae9cd6050e09af901a4de
npx wrangler d1 create university-emdash-db --location wnam            # put the new UUID in wrangler.jsonc
npx wrangler d1 create university-emdash-db-preview --location wnam
npx wrangler r2 bucket create university-emdash-media
npx wrangler r2 bucket create university-emdash-media-preview
npx wrangler kv namespace create university-emdash-session             # put the new id in wrangler.jsonc
npx wrangler kv namespace create university-emdash-session-preview
# Access: create the two apps under "Access" below; copy each AUD tag
npm ci && (cd scripts/emdash && npm ci && node build-seed.mjs)
# --config wrangler.jsonc on every secret put: after a build, wrangler otherwise follows dist/ and can hit the wrong Worker
npx wrangler secret put CF_ACCESS_AUDIENCE --config wrangler.jsonc                  # prod AUD
npx wrangler secret put CF_ACCESS_AUDIENCE --config wrangler.jsonc --env preview    # preview AUD
npx emdash secrets generate        # copy the emdash_enc_v1_... line, paste it at the next prompt
npx wrangler secret put EMDASH_ENCRYPTION_KEY --config wrangler.jsonc
npx wrangler secret put EMDASH_ENCRYPTION_KEY --config wrangler.jsonc --env preview # a different generated key
npx emdash seed --on-conflict update && node scripts/emdash/d1-sql.mjs   # seeded SQLite -> scripts/emdash/out/d1-load.sql
bash scripts/infra/deploy.sh preview --load-content                      # NEW, empty D1 only: loads every page, menu and search index
# First admin: a named eTop person opens <preview>/_emdash/admin first; in the setup wizard choose "Empty site"
(cd scripts/emdash && node parity.mjs --candidate <preview>)             # must exit 0
```

**Content is the part you cannot rebuild from git** once editors start working in the CMS. The markdown in
`src/content/docs/` is frozen at the migration. After cutover, the D1 database is the only copy of
edited pages. Cloudflare D1 Time Travel restores any minute in the last 30 days on Workers Paid (7 on Free)
(`npx wrangler d1 time-travel restore university-emdash-db --timestamp <ISO>`). Anything older needs an
export (`npx wrangler d1 export university-emdash-db --remote --output university.sql`). Scheduling that
export is open (see Known traps).

## Known traps

- **2026-10-02** EmDash needs `output: "server"`, so it cannot run on the existing Pages project. It is a new
  Worker, and the cutover moves the custom domain from Pages to the Worker.
- **2026-10-02** `wrangler deploy` does not migrate D1. Use `scripts/infra/deploy.sh`, which does. A new table
  without its migration returns 500s.
- **2026-10-02** An Access path of `/_emdash` matches only that exact path. `/_emdash/admin` was reachable without a
  login until `/_emdash/*` was added. List both.
- **2026-10-02** The first identity through Access becomes EmDash **Admin**, and the setup wizard opens for it. On the preview that
  was BJ (via Entra SSO), and the wizard got **"Empty site"**: the content was already loaded by `deploy.sh --load-content`, and
  both wizard options seed with `onConflict: skip`, but "Empty site" writes no content at all. Do the same at production cutover.
  Never let the E2E service token be the first identity.
- **2026-10-02** `preview_urls: false` in both envs. Cloudflare's per-version preview hostnames would sit outside
  the Access app and expose the admin.
- **2026-10-02** The Access policy that requires the Entra login method rejects service tokens. Automation needs
  its own *Service Auth* policy, on the preview app only.
- **2026-10-02** EmDash's `dev-bypass` sign-in exists only under `astro dev`. It returns 403 on any deployed Worker.
  That is why the E2E uses a service token + API token against the preview.
- **2026-10-02** Editing `src/content/docs/*.md` after cutover changes nothing on the site. Re-running
  `apply.mjs --overwrite` after cutover would **overwrite editors' work**. `apply.mjs` refuses to touch pages edited in
  the CMS unless you pass `--overwrite`.
- **2026-10-02** 34 internal links already 404 on the live site (old GitBook `.md` links). They are listed in
  `scripts/emdash/out/parity-report.md` and do not block cutover.
- **2026-10-02** Node: EmDash 1.1 wants `^22.22.2 || ^24.15 || >=26`. 22.22.0 only warns.
- **2026-10-02** `emdash seed` gives pages **fresh IDs on every run**, so menu items loaded with old IDs point at nothing
  and the sidebar silently loses its page links. `d1-sql.mjs` re-points menu links by slug. Found by the visual diff, not by parity.
- **2026-10-02** Code blocks render as a plain `<pre>`, with no syntax colouring or copy button: Shiki needs runtime
  WebAssembly compilation, which Workers block. One block on the whole site is affected. This was accepted.
- **2026-10-02** Starlight's markdown engine (satteri) is stubbed in the Worker (`src/stubs/satteri.mjs`). Anything that tries to
  compile markdown at request time throws. Pages are Portable Text, so nothing should.
- **2026-10-02** "Last updated" shows the **migration date** until someone edits a page: git dates were not carried over.
- **2026-10-02** Search is `/api/search` (public, published pages only). Don't point it at `/_emdash/api/search`, which is behind Access.
- **2026-10-02** Body text wraps a few pixels differently from the old site (Starlight 0.30 to 0.42 font metrics). Accepted by the lead.
- **Open (blocks editor images)**: images uploaded in the editor are served from `/_emdash/api/media/file/*`, which Access
  covers, so visitors get a 302 to the login page instead of the picture. It needs an Access **Bypass (Everyone)** app for that path
  (designed in infra's notes, waiting on BJ). Check: anonymous `GET /_emdash/api/media/file/does-not-exist` returns EmDash's 404, not 302.
  Until then, the staff how-to tells editors to ask BJ before adding pictures.
- **2026-10-04** The EmDash editor writes its list's start number and a shared `listId` on **every** item of a numbered list it saves.
  The theme counts `listStart` only on a list's first item; reading it on every item split 23 saved pages (found by a real-editor round-trip, `tests/e2e/roundtrip.mjs`).
- **2026-10-04** Note boxes and collapsible sections loaded before 2026-10-04 are the old single locked block. They still render, but
  their text can only be changed after `scripts/emdash/flatten-boxes.mjs --apply` rewrites them as start/end markers (dry run by default; refuses production without `--production`).
- **2026-10-04** `astro dev` fails with "Tsconfig not found astro/tsconfigs/strict" in a git worktree under `.claude/worktrees/` of a checkout
  that has no `node_modules`: Vite picks up the outer checkout's `tsconfig.json`. Run the dev server from a copy outside the checkout.
- **Open**: no scheduled D1 export beyond Time Travel's window.
