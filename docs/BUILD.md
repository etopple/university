## What it is

eTop University is eTop's public help and learning site: self-help guides for clients, eTop process pages, policies and the team page. Anyone can read it without a login. eTop staff edit pages in a browser at `/_emdash/admin` and publish without touching git. It is built with Astro + Starlight (look and navigation) and EmDash, Cloudflare's open-source CMS (content store).

It is **not** a client portal. It holds no client data. Only the editor (`/_emdash`) needs a login. The old GitBook markdown on `website` is now only the migration source: editing it no longer changes the site.

## Deploy

Run from the repo root of the shipping branch after `npm ci` and `npx wrangler login`.

```bash
bash scripts/infra/deploy.sh preview                     # everyday code deploy to preview
bash scripts/infra/deploy.sh production                  # everyday code deploy; type 'production' to confirm
bash scripts/infra/deploy.sh <env> --migrate             # only when an EmDash upgrade adds core migrations; needs CLOUDFLARE_API_TOKEN
bash scripts/infra/deploy.sh <env> --load-content        # EMPTY D1 only (first load). Overwrites pages with the seed.
```

- The env is picked at **build time** (`CLOUDFLARE_ENV`), so deploy takes no `--env`. Commands that read `wrangler.jsonc` directly (`d1 execute`, `secret put`) need `--config wrangler.jsonc --env preview`.
- The default (code-only) **refuses** if the build's EmDash migrations or version differ from what is deployed. It prints `REFUSED` and points to `--migrate`. It touches no data.
- `wrangler deploy` never runs D1 migrations. Never run `--load-content` on production after editors have started working.
- A custom-domain deploy is refused (error 100117) while another DNS record exists for the host.
- Any new hostname must be added to the prod Access app **before** it is attached.

**Confirm it worked:** `deploy.sh` prints `VERIFY OK`. Then run `python scripts/infra/smoke.py` (read-only; PASS expected) and the checks under Health check.

## Roll back

- **Bad code deploy:** redeploy the previous good commit with `deploy.sh production`. Unverified: `wrangler rollback` was not tested for this Worker; list versions first with `npx wrangler deployments list`.
- **Bad content edit:** D1 Time Travel restores any minute in the last 30 days (Workers Paid): `npx wrangler d1 time-travel restore university-emdash-db --timestamp <ISO>`.
- **Back to Pages (custom domains):** per `docs/INFRA.md` on PR #39: `DELETE /accounts/<acct>/workers/domains/<id>` for the host (this also removes its DNS record), recreate the proxied CNAME to `etop-university.pages.dev`, and re-add the host to Pages project `etop-university`. The old Pages deployment still serves at `etop-university.pages.dev`. Do this only if that deployment still exists.

## Rebuild from zero

1. Create resources (account `44c7bfb7295ae9cd6050e09af901a4de`), then put the new IDs in `wrangler.jsonc`:
```bash
export CLOUDFLARE_ACCOUNT_ID=44c7bfb7295ae9cd6050e09af901a4de
npx wrangler d1 create university-emdash-db --location wnam
npx wrangler d1 create university-emdash-db-preview --location wnam
npx wrangler r2 bucket create university-emdash-media
npx wrangler r2 bucket create university-emdash-media-preview
npx wrangler kv namespace create university-emdash-session
npx wrangler kv namespace create university-emdash-session-preview
```
2. Create the two Access apps (see Access) and copy each AUD tag.
3. `npm ci && (cd scripts/emdash && npm ci && node build-seed.mjs)`.
4. Set secrets, with `--config wrangler.jsonc` on every `secret put`: `CF_ACCESS_AUDIENCE` (add `--env preview` for preview) and `EMDASH_ENCRYPTION_KEY` (generate one per env with `npx emdash secrets generate`).
5. `npx emdash seed --on-conflict update && node scripts/emdash/d1-sql.mjs`, then `bash scripts/infra/deploy.sh preview --load-content`. Repeat for `production`.
6. First admin: a named eTop person opens `<site>/_emdash/admin` through Access and picks **"Empty site"** in the wizard. Then re-point the sidebar (the wizard strips page links, issue #25): export the menu with `npx wrangler d1 execute DB --config wrangler.jsonc [--env preview] --remote --json --command "SELECT * FROM _emdash_menu_items" > items.json`, run `node scripts/emdash/relink-menu.mjs --items items.json`, review and run the generated `out/relink-menu.sql` with `--remote --file`. `deploy.sh` VERIFY must then pass.
7. Parity gate against the old site: `(cd scripts/emdash && node parity.mjs --candidate <url>)` must exit 0.
8. Attach hosts: the `routes` block in `wrangler.jsonc` (both `custom_domain: true`), after any CNAME for the host is gone; deploy production.

**Content is the part git cannot rebuild.** After cutover D1 is the only copy of edited pages. Time Travel covers 30 days. For older recovery use `npx wrangler d1 export university-emdash-db --remote --output university.sql`. No scheduled export exists yet.
